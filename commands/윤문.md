# /윤문

`urimal-for-socialworker` 스킬을 트리거합니다. v2.1부터 Fast Path(monolith 1콜) 디폴트, Strict(6+1인 파이프라인)는 옵션.

## 사용

```
/윤문 [입력]
/윤문 docs/2026_사업계획서.hwpx
/윤문 docs/주간업무보고서.hwp 정밀 모드
/윤문 docs/사업보고서.hwp --strict           # 6+1인 파이프라인 강제
/윤문 (붙여넣은 텍스트) 장르: 보고서
```

## 입력 처리 규칙

`urimal-for-socialworker` 스킬을 호출하여 입력을 처리한다. 다음 단계를 따른다.

1. **입력 정규화**
   - 인자가 파일 경로(`.hwp`, `.hwpx`, `.pdf`, `.docx`, `.xlsx`)이면 → `kordoc` 스킬을 먼저 호출하여 마크다운으로 변환한 뒤 그 결과를 윤문 대상으로 사용
   - 인자가 `.txt`, `.md`이면 → 직접 Read
   - 인자가 텍스트(붙여넣기)이면 → 그대로 입력

2. **모드 자동 결정** — 다음 우선순위
   - `--strict` 명시 → strict 모드 (6+1인 파이프라인)
   - 입력 8,000자 초과 → strict 자동 승급 (사용자에 1줄 고지)
   - 사용자가 "특정 카테고리만 다시" / "이 문단만" 등 부분 재실행 → strict 자동
   - 그 외 → **fast 모드 (디폴트)** — `urimal-monolith` 1콜

3. **옵션 파싱** — 자연어 옵션을 다음 키로 매핑
   - "정밀 모드" / "opus" / "최고 품질" → `model: "opus"` (`claude-opus-5`)
   - 기본값 → `model: "sonnet"` (`claude-sonnet-5`)
   - "강도: 보수적" / "원문 톤 살려줘" → `over_polish_threshold: 0.20`
   - "장르: 계획서|보고서|안내문|공적연설" → `genre_hint`
   - "최소심각도: S1|S2|S3" → `min_severity` (strict 모드만 의미 있음)

4. **스킬 호출** — `urimal-for-socialworker` 오케스트레이터(`scripts/orchestrator.md`)를 트리거하고 Phase 0부터 진행

5. **출력**
   - **Fast**: `_workspace/{run_id}/final.md` (본문 끝 `<!-- URIMAL-SUMMARY -->` 메타 블록 포함)
   - **Strict**: `_workspace/{run_id}/final.md` + `summary.md`

## 동작 정책

- **수치·고유명사·기관명·인용은 절대 변경 금지** (Do-NOT list 엄수)
- **변경률 30% 초과 시 경고, 50% 초과 시 강제 중단**
- **차별·시혜 표현(SW-14) 잔존 시** Fast 모드라면 즉시 strict 권고
- 결과 등급 B 이하면 "정밀 검증이 필요하면 `--strict`로 재실행" 자동 안내

## Fast vs Strict 차이

| 항목 | Fast (디폴트) | Strict |
|------|--------------|--------|
| 에이전트 호출 | 1회 (urimal-monolith) | 6~10회 (sw-detector + ai-detector + rewriter + auditor + reviewer) |
| Wall-clock (5,000자) | 2~3분 | 15~25분 |
| 도구 호출 | 3회 캡 | ~30회 |
| 출력 | final.md (메타 블록 포함) | final.md + summary.md |
| 자동 승급 | — | 8,000자+ / 부분 재실행 / SW-14 잔존 |
